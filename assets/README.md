# Assets — VitaShop

Staging area for project assets. **This folder moves into the code repository** once it exists.

Source: DEC-016, DEC-026

---

## Structure

```
assets/
├── README.md              ← this file
├── brand/
│   ├── logo.png           ← the site logo. REPLACEABLE
│   ├── logo.svg           ← vector version, if available
│   └── favicon.png
├── products/
│   ├── products.csv       ← 🔴 the source of truth for product data
│   ├── placeholder.svg    ← fallback for a product with no image
│   └── *.jpg              ← one image per product, flat
└── ui/
    └── (icons, backgrounds — only if the design direction needs them)
```

⚠️ **Product images are flat, not in per-product folders.** `products.csv` maps each row to its image via the `image_file` column. This suits how images actually arrive — dropped in one at a time — and avoids renaming files the user placed.

**Multiple images per product** (Table 1, field 10 allows 1–4): add `image_file_2`, `image_file_3`, `image_file_4` columns when needed. One is sufficient for now.

## 🔴 The logo is swappable by design

`brand/logo.png` is referenced through **one** constant in the code. Replacing the file replaces the logo everywhere — no code change, no search-and-replace.

```
✅ import logo from '@/assets/brand/logo.png'   — one import, reused
❌ hardcoding the filename in each component
```

Keep the same filename when swapping. If dimensions change materially, check the header and the mobile layout.

## 🔴 products.csv — the source of truth

**One row per product. The seed script reads this file. Nothing else defines the catalogue.**

Encoding: **UTF-8 with BOM** so Excel opens Hebrew correctly. If you edit in Excel, save as *CSV UTF-8*, not plain CSV — plain CSV mangles Hebrew.

| Column | Table 1 field | Notes |
|---|:--:|---|

| `image_file` | 10 | Exact filename in this folder |
| `name_he` | 02 | Hebrew product name |
| `name_en` | 02 | English name — needed only if ISSUE-011 resolves to option B |
| `category` | 03 | 🔴 Exactly one, from the six approved categories |
| `brand` | 04 | |
| `dosage_form` | 05 | 🔴 One of: `כמוסות` `טבליות` `טיפות` `אבקה` `סירופ` — DEC-028 |
| `package_quantity` | 06 | Integer > 0 |
| `price` | 08 | Decimal > 0 |
| `stock_quantity` | 09 | Integer >= 0 |
| `usage_instructions` | 07 | 🔴 Quote the manufacturer. Never phrase as a recommendation |
| `description` | 11 | |
| `warnings_allergens` | 12 | 🔴 Never empty |
| `active_ingredients` | 13 | Format: `name:amount:unit|name:amount:unit` |

## 🔴 The two-tier rule for filling data

**Not all fields carry the same risk.** This distinction matters:

| Tier | Fields | Rule |
|---|---|---|
| **Invent freely** | `price` · `stock_quantity` · `description` · `health_goals` | This is a demo store. Make them up. Nothing depends on their accuracy |
| 🔴 **Must be accurate** | `active_ingredients` · `warnings_allergens` · `usage_instructions` · `package_quantity` | These describe a **real product**. A wrong allergen is a safety problem, not a cosmetic one |

**Why:** the catalogue names real products from real brands. A user reading "contains no soy" on a product that does contain soy has been misled about something that matters. Prices are obviously fictional in a student demo; allergen data does not read as fictional.

### 🔴 Where the accurate tier comes from

```
✅ The manufacturer's official product page
✅ A photograph of the actual package label
✅ An authorised distributor's listing

❌ An agent's recollection of what the product contains
❌ An agent's web search summary, unverified
❌ Another product from the same brand, assumed similar
```

⚠️ **An agent may pre-fill these fields from the manufacturer's official page, with the URL recorded in `data_source`.** The user then spot-checks and sets `verified = yes`. An agent must never fill them from memory, and must never leave `verified` blank while claiming the row is complete.

**A row with `verified` blank is not seeded into a catalogue anyone else will see.**

## Adding a product

```
1. Drop the image into assets/products/
2. Add a row to products.csv — slug, image_file, name, brand, category
3. Fill the invent-freely tier: price, stock, description
4. Fill the accurate tier from the manufacturer's page or the package label
5. Record the URL in data_source
6. Set verified = yes once checked
```

🔴 **Steps 4–6 are not optional for a real product.** A row without them stays out of the catalogue.
